# Fabric Integration Plan for AIPrivateSearch

## Overview

This document adapts the Fabric install guide (`aips-fabric-install.md`) to integrate with AIPrivateSearch's existing architecture. Fabric provides remote prompt enhancement using Claude Haiku before queries are processed locally by Ollama.

## Architecture (Adapted for AIPS)

```
User selects collection → types query → clicks "Enhance" (optional)
        ↓
Express server → FabricService → Fabric server (enhance_[collection] pattern / Haiku)
        ↓
Enhanced prompt returned to UI → user reviews
        ↓
User clicks Submit → existing SearchOrchestrator → Ollama (local) → answer
```

**Key principle**: Fabric handles prompt enhancement only. All document processing, search, and answers remain local via Ollama. No document content leaves the user's machine.

## How It Maps to Existing AIPS Flow

### Current Flow (without Fabric)
```
User query → [optional: prepend meta-prompt] → SearchOrchestrator → Ollama → answer
```

### New Flow (with Fabric)
```
User query → [click Enhance] → FabricService → enhanced query returned to UI
           → User reviews/edits → Submit → SearchOrchestrator → Ollama → answer
```

The enhancement is **optional and user-controlled**. The existing `addMetaPrompt` checkbox can remain as a local fallback when Fabric is unavailable.

## Pattern Generation Strategy

AIPS already has rich collection metadata in `meta-prompts.json` (document types, word counts, topics, keywords, AI analysis). This is the perfect source for generating Fabric patterns.

### Pattern naming convention
```
enhance_[collection-name]
```
Examples: `enhance_USA-History`, `enhance_Family-Documents`, `enhance_Law-Office`

### When to generate/update patterns
- When a collection is created (from Collections page)
- When documents are added/removed from a collection
- When Document Index Cards are regenerated (since that updates metadata)
- When collection is re-embedded
- Manual trigger from Collections page ("Regenerate Pattern" button)

**Trigger points in existing code:**
- `routes/documents.mjs` → `POST /collections/create` — generate pattern after directory creation
- `routes/documents.mjs` → `POST /collections/:collection/upload` — regenerate pattern after file upload
- `routes/documents.mjs` → `DELETE /collections/:collection/files/:filename` — regenerate pattern after file removal
- `routes/multiSearch.mjs` → `POST /document-index-create` — regenerate pattern after index cards are built (best metadata available at this point)
- `routes/documents.mjs` → `POST /collections/:collection/index/:filename` — regenerate after embedding

The pattern generation should be fire-and-forget (non-blocking) so it doesn't slow down the user's action.

### Pattern content (built from existing meta-prompts.json)
The `generatePattern.mjs` script reads the collection's entry in `meta-prompts.json` and builds a Fabric system prompt that includes:
- Collection name and document count
- Document types and topics
- Key terms and vocabulary
- Instructions for prompt enhancement specific to that domain

## Ubuntu Server Setup (Same as fabric-install.md)

No changes needed to the server setup. Follow `aips-fabric-install.md`:
1. Install Go
2. Install Fabric
3. Get Anthropic API key
4. Configure Fabric with `fabric --setup`
5. Configure DNS (GoDaddy A record for fabric.formr.net)
6. Start Fabric with systemd (`--serve --address :8081 --api-key`)
7. Configure Caddy reverse proxy (`/etc/caddy/sites/fabric-formr-net.caddy`)
8. Test with `curl`

> **Note**: PM2 does not work with Go binaries. Fabric runs as a systemd service.

## Security Considerations (AIPS-Specific)

- **API key storage**: `FABRIC_API_KEY` goes in `.env-aips` (already gitignored, already used for DB credentials)
- **No document content sent to Fabric**: Only the user's query text is sent for enhancement. Collection metadata in patterns is uploaded once during generation (summaries only, not full documents)
- **Fail-fast**: If Fabric is unreachable, the enhance button shows an error. Search still works normally with the raw query
- **Input validation**: Collection name validated against `CollectionsUtil.getCollectionNames()` before building pattern name (prevents injection)
- **Rate limiting**: Add to the `/api/fabric/enhance` route to prevent cost runaway

## What NOT to Change

- `SearchOrchestrator.mjs` — receives the query (enhanced or not), no awareness of Fabric needed
- `OllamaService.mjs` — still handles all generation
- `ScoringService.mjs` — scores the answer regardless of whether prompt was enhanced
- Existing search methods — all 7 methods work the same way
- `system-prompts.json` — assistant personality is separate from query enhancement
- Document processing/embedding pipeline — completely unrelated to Fabric

## Comparison: Current Meta-Prompt vs Fabric Enhancement

| Aspect | Current `addMetaPrompt` | Fabric Enhancement |
|--------|------------------------|-------------------|
| Intelligence | Static text prepended | AI-rewritten query with domain awareness |
| Cost | Free (local) | ~$0.001 per enhancement |
| Quality | Generic collection context | Tailored, specific, structured query |
| User control | On/off checkbox | Review and edit before submit |
| Availability | Always available | Requires remote server |
| Fallback | N/A | Falls back to addMetaPrompt or raw query |

Both can coexist. Fabric is the premium option; meta-prompt is the always-available local fallback.
